01
Overview & Core Philosophy

The Financial Goals module empowers users to translate financial aspirations into structured, actionable plans. Unlike budgets (controlling spending) or debt management (eliminating liabilities), Goals are forward-looking: they describe a future state worth saving toward.

Design principle: Every interaction must feel like progress. The system rewards small wins, never punishes delays, and always offers a constructive next step. Behavioral motivation is built into every calculation and recommendation.

Core Pillars

Clarity
Each goal has a specific target, a concrete timeline, and a known required monthly contribution. Users never wonder "am I on track?"
Motivation
Milestone badges, completion animations, streak recognition, and progress visualizations keep users engaged across the full journey.
Realism
The system calculates feasibility against disposable income and recommends adjustments when goals are mathematically unachievable.
Priority
Users manage multiple goals simultaneously. Priority ordering ensures limited income is directed where it matters most first.

COMPLETED Transition Flow

Trigger detection
After any contribution is recorded, system checks: currentSavedAmount ≥ targetAmount. If true, status → COMPLETED, completedAt = now().
Celebration sequence
Full-screen confetti animation + achievement sound + PCT_100 milestone badge unlocked. Push notification: "🎉 Goal achieved!" fires within 5 seconds.
Budget cleanup prompt
If goal was linked to a budget category: "Your [Category] budget allocation is now free. Would you like to redirect it?" — suggest highest-priority active goal or Emergency Fund.
30-day archive prompt
30 days after completion, push: "Archive [Goal Name]?" Archived goals move to History. If user does nothing, auto-archive at day 30.
ARCHIVED
Contribution history preserved. Milestone badges remain in user's badge collection. Counts toward achievementRate in analytics.

CANCELLED Transition Flow

Cancellation initiated
User taps Cancel Goal. Must provide cancelReason (required, 1–200 chars). Confirmation dialog: "Your contribution history will be preserved."
Budget redirect
Same prompt as COMPLETED: freed monthly allocation offered for redirection to another goal.
Immediate archive
CANCELLED → ARCHIVED with no 30-day grace period. Contributions preserved. Does NOT count toward achievementRate numerator (only denominator).

Priority Management

Priority Levels

CRITICALCRITICALFirst slice of disposable income5× weightAlways pinned top

MEDIUMMEDIUMThird allocation round2× weightDefault position

OPTIONALOPTIONALOnly if surplus exists0.5× weightCollapsed by default

Priority Ordering Rules

  • Each goal has a priorityOrder integer unique across all goals (not per-priority-level).
  • Lower number = higher order (goal #1 is the most important).
  • Users reorder via drag-and-drop in the Goals list; system re-integers orders compactly (1, 2, 3 …) on each reorder.
  • Changing priority level (e.g. MEDIUM → HIGH) moves the goal to position 1 within the new priority level group without changing other goals' relative order.
  • A priority reorder event is logged in GoalTimeline but does NOT create a GoalContribution record.

Priority-Weighted Contribution Recommendation

Multi-Goal Allocation
totalDisposable = salary.disposableIncome − debt.totalMonthlyPayments − emf.monthlyContribution

For each ACTIVE goal, sorted by priorityOrder:
  allocate MIN(goal.requiredMonthlyContribution, remainingDisposable)
  remainingDisposable -= allocated
  if remainingDisposable ≤ 0: lower-priority goals get 0 recommendation

Goals that received 0 allocation → flag as "constrained" in recommendations
EMF Gate (BR-GOL-01): If emergencyFund.currentMilestoneLevel = LEVEL_0 and the user attempts to set a goal as CRITICAL, show advisory: "Consider reaching your 1-month Emergency Fund before marking goals as Critical." The action is not blocked — it is advisory only.
06
Saving Plan Engine

All plan calculations are derived at read time. No plan values are stored — they are always computed from the current goal state and current date.

Core Computed Values

Base Metrics
currentSavedAmount = SUM(contribution.amount) for all non-deleted contributions
remainingAmount = MAX(0, targetAmount − currentSavedAmount)
completionPct = currentSavedAmount / targetAmount × 100

daysToTarget = targetDate − TODAY (null if no targetDate)
weeksToTarget = daysToTarget / 7
monthsToTarget = daysToTarget / 30.4375
Required Contribution Rates
requiredDailyContribution = CEIL(remainingAmount / daysToTarget) [if daysToTarget > 0]
requiredWeeklyContribution = CEIL(remainingAmount / weeksToTarget)
requiredMonthlyContribution = CEIL(remainingAmount / monthsToTarget)

If targetDate is null: these values are null (shown as "—" in UI)
Average Contribution & Estimated Completion
monthsActive = FLOOR(days since createdAt / 30.4375) + 1

avgMonthlyContribution = SUM(deposits in last 3 calendar months) / 3
  where deposits = contributions with amount > 0

monthsToCompletion = CEIL(remainingAmount / avgMonthlyContribution) [if avg > 0]
estimatedCompletionDate = TODAY + monthsToCompletion months
Feasibility Score
feasibilityRatio = disposableIncome / requiredMonthlyContribution

FULLY_FEASIBLE → feasibilityRatio ≥ 1.00 (required ≤ 100% disposable)
ACHIEVABLE → 0.70 ≤ ratio < 1.00 (requires 70–100% — challenging)
CHALLENGING → 0.40 ≤ ratio < 0.70 (requires more than available)
UNREALISTIC → ratio < 0.40 (required > 2.5× available)

If targetDate is null: feasibilityScore = null (goal has open timeline)

Plan Update Triggers

The plan recalculates instantly whenever any of the following change:

Contribution Added / Removed
currentSavedAmount changes → all derived metrics update
targetAmount Changed
remainingAmount and all rate calculations update
targetDate Changed
Required contribution rates and feasibility recalculate
Date Advances (Daily)
daysToTarget decrements; requiredDailyContribution increases; estimatedCompletion shifts
Salary / Income Changes
disposableIncome updates → feasibilityScore and multi-goal allocation recalculate

Plan Display Priority

The UI displays contribution rates in the following priority order, showing the most actionable view first:

  1. Required Monthly — always shown (even if targetDate is null, shows "no deadline set")
  2. Estimated Completion — shown below required monthly with current avg rate
  3. Required Daily / Weekly — shown in expanded plan view or when goal deadline < 90 days
  4. Feasibility label — color-coded badge shown alongside required monthly

Contribution Recording Flow

1. Input validation
amount must be integer > 0 (or < 0 for withdrawal). amount + currentSavedAmount must be ≥ 0 (no negative balance). Note required if amount < 0.
2. Balance snapshot
Compute balanceAfter = currentSavedAmount + amount. Store on the contribution record for audit trail.
3. Milestone check
Check if completionPct crossed any new milestone (10/25/50/75/90/100%). If yes: insert GoalMilestone record, set contribution.milestoneReached.
4. Budget category sync
If goal.budgetCategoryId is set: create a corresponding expense in that budget category for the same amount (type: GOAL_CONTRIBUTION).
5. Completion check
If balanceAfter ≥ targetAmount: trigger COMPLETED transition (Section 04 flow).
6. Timeline event
Append GoalTimeline event: CONTRIBUTION_ADDED with amount, type, balanceAfter, milestoneReached.
7. UI update
Recalculate all plan metrics, update progress ring, refresh dashboard KPIs. If milestone crossed: show badge animation.

Auto-Contribution Flow (isAutoContribute = true)

Daily system check on contributionDay
if goal.status ≠ ACTIVE: skip
if goal.isPaused = true: skip
if today = goal.contributionDay (day of month):
  if goal.budgetCategoryId is set:
    available = budgetCategory.remaining − budgetCategory.reservedForOtherGoals
    amount = MIN(goal.monthlyContribution, available)
  else:
    amount = goal.monthlyContribution
  if amount > 0: record AUTO_MONTHLY contribution
  if amount = 0: send CONTRIBUTION_INSUFFICIENT notification

Withdrawal Rules

  • Withdrawals are allowed at any time from ACTIVE or PAUSED goals.
  • Balance floor: currentSavedAmount cannot go below 0. System rejects any withdrawal that would cause a negative balance.
  • Note is required for all withdrawals.
  • A withdrawal does NOT change goal status — the goal remains ACTIVE.
  • If a withdrawal reduces currentSavedAmount below a previously reached milestone, the milestone badge is NOT revoked (BR-GOL-04).
  • Withdrawals count against contribution consistency score (they don't count as a "contribution month").

Suggested Contribution Formula

Per-Goal Contribution Suggestion
base = requiredMonthlyContribution (from Saving Plan Engine)

if base > 0.5 × disposableIncome:
  suggest = 0.5 × disposableIncome (cap at 50% of disposable)
elif base > 0.3 × disposableIncome AND goal.priority = OPTIONAL:
  suggest = 0.2 × disposableIncome (reduce for low-priority goals)
else:
  suggest = base

finalSuggestion = MAX(100, suggest) // minimum $1 suggestion
Tone guidelines: Recommendations use second person, present tense, and specific numbers. Never "you should" — always "you could" or direct action verbs. Frame delay as an opportunity, never a failure. Example: "Extend to March 2026" not "You're behind schedule."

Goal Health Score

A single 0–100 score summarizing how well the user's overall goal portfolio is performing. Computed across all ACTIVE goals, refreshed at each screen load.

Score Components

35
Progress Rate
Weighted avg of actual vs expected progress across all ACTIVE goals.
On track or ahead = 35 pts. 1–10% behind = 25 pts. 11–25% behind = 15 pts. 26–50% behind = 8 pts. >50% behind or no date = 0 pts.
25
Contribution Consistency
monthsWithContribution / monthsActive × 100, scaled to 25 pts.
Averaged across all ACTIVE goals. A month counts if any positive contribution was recorded.
20
Goal Realism
For each goal: requiredMonthly vs disposableIncome.
≤15% disposable = 20 pts. 16–25% = 15 pts. 26–35% = 10 pts. 36–50% = 5 pts. >50% = 0.
Averaged across all goals (goals without targetDate treated as 15 pts neutral).
10
Priority Balance
No CRITICAL goals off-track = 10 pts. 1 CRITICAL goal off-track = 5 pts. 2+ CRITICAL off-track = 0 pts. No CRITICAL goals = 8 pts (neutral).
10
Timeline Clarity
% of ACTIVE goals with a targetDate set, scaled to 10 pts.
All goals have dates = 10. No goals have dates = 0. Fraction = proportional.

Notification Frequency Rules

  • Maximum 2 notifications per goal per day.
  • Maximum 5 notifications total per day across all goals.
  • NOT-07 (Off Track Alert) fires at most once per 14 days per goal.
  • NOT-05 (Inactive) fires once on day 60; re-arms 30 days later if still inactive.
  • All notifications respect system-level Do Not Disturb settings.
  • Users can disable individual notification types per goal in settings.

Business Rules

IDRule
BR-GOL-01targetAmount minimum is 100 centimes (≥ 1.00 in base currency).
BR-GOL-02priorityOrder integers must be unique across all goals (ACTIVE + PAUSED). Gaps are allowed. Archived/Cancelled goals are excluded from ordering.
BR-GOL-03COMPLETED status is irreversible EXCEPT when a contribution deletion reduces currentSavedAmount below targetAmount (EC-05). In that case, status reverts to ACTIVE automatically.
BR-GOL-04GoalMilestone badges are never revoked, even if balance drops below the milestone threshold after a withdrawal.
BR-GOL-05DRAFT goals are excluded from all dashboard KPIs, health score calculations, analytics, and notification triggers.
BR-GOL-06Hard deletion of goals and contributions is prohibited. All deletions are soft (deletedAt timestamp). Audit trail must remain permanently intact.
BR-GOL-07balanceAfter on each GoalContribution must equal the running sum of all non-deleted contributions for that goal as of that contribution's date. Verified on insert.
BR-GOL-08contributionDay is capped at 28 to handle all month lengths. Days 29–31 are not allowed.
BR-GOL-09Auto-contributions (AUTO_MONTHLY) fire only for ACTIVE goals where isPaused = false. PAUSED, COMPLETED, CANCELLED, and ARCHIVED goals receive no auto-contributions.
BR-GOL-10Priority reordering does not create a GoalContribution record. It creates a PRIORITY_CHANGED GoalTimelineEvent only.
