SPEC-EMF-001 — Emergency Fund

Emergency Fund System

Complete functional specification for the Emergency Fund module of Finance Bag. Covers milestone architecture, contribution lifecycle, progress calculations, behavioral health scoring, smart recommendations, automation, and future scalability.

01 Core Philosophy

The Emergency Fund is the foundation of financial resilience. Without it, every unexpected expense — a medical bill, a car repair, a job loss — becomes a crisis. With it, the user gains a buffer that transforms emergencies into inconveniences.

🛡️
Founding Principle The Emergency Fund is not a savings account — it is financial armor. The system must educate, motivate, and coach — not just track numbers. Every dirham contributed is a step toward the state where unexpected events no longer cause financial panic.

Three Roles of the System

RoleWhat the System DoesImplementation
EducatorExplains why each milestone level matters and what it actually protects againstContextual descriptions on milestone cards; health score explanations with plain-language impact statements
MotivatorMakes every contribution feel meaningful, regardless of amountProgress ring, milestone badges, "You are X% financially protected" messaging, celebration animations
CoachGuides users toward the right target, pace, and priority relative to other financial goalsSmart recommendations, health score, DTI-aware contribution suggestions, completion date estimates

Cross-Module Integration

  • Budget (SPEC-BUD-001): Monthly contribution is an EMERGENCY_FUND category — changes sync automatically, no double entry.
  • Salary (SPEC-SAL-001): Monthly essential expenses are pre-filled from the budget allocation pattern. Target amounts derive from this figure.
  • Health Score (SPEC-SAL-001): Fund completion contributes 20 points. Contribution consistency adds weight within that 20-point range.
  • Debt (SPEC-DBT-001): When DTI >40%, the system recommends reaching Level 1 only, then shifting surplus toward debt — never recommending both simultaneously unless income permits.

Milestone Crossing Behavior

When a contribution causes currentAmount to cross a milestone threshold for the first time:

  1. The contribution record gets milestoneReached set to that level.
  2. A celebration animation triggers in the UI (confetti, ripple).
  3. A milestone notification fires immediately (see §14).
  4. A milestone badge is unlocked and displayed on the user's profile.
  5. The system suggests the next milestone as the new target if the user hasn't already set it.
⚠️
Milestone Re-crossing on Withdrawal If a withdrawal drops the balance below a milestone threshold, the milestone is not revoked — the badge is retained, but the progress bar reflects the current real balance. A contextual note appears: "Your balance has dipped below your Level 2 milestone. Resume contributions to rebuild."

Target Amount Derivation

targetAmount = if targetType = '1_month': monthlyExpenses × 1 if targetType = '3_months': monthlyExpenses × 3 if targetType = '6_months': monthlyExpenses × 6 if targetType = 'custom': user-entered customTargetAmount -- targetAmount refreshes automatically when monthlyExpenses changes -- but never retroactively changes historical balanceAfter values

Monthly Expenses Pre-fill Logic

During onboarding or first visit to the Emergency Fund module, the system pre-fills monthlyExpenses by summing the allocated amounts of all ESSENTIAL_EXPENSE budget categories from the current budget period. The user can override this figure freely — it is just a starting suggestion, not a binding value.

Recording a Contribution (User Flow)

  1. User taps "Add Contribution" and chooses type (Deposit, Bonus, or Withdrawal).
  2. User enters amount, date (default: today), optional note, and optional tags.
  3. System computes balanceAfter = currentAmount + amount and checks for milestone crossing.
  4. If balance < 0: block with error "Withdrawal exceeds fund balance."
  5. Contribution is saved. EmergencyFund.currentAmount is updated.
  6. Budget module is notified if the contribution links to a budget period (DEPOSIT / AUTO types).
  7. Milestone check runs; celebration triggered if appropriate.

06 Progress Calculations

Core Formulas

-- Completion percentage completionPct = currentAmount / targetAmount × 100 → capped at display maximum of 100% (can exceed in storage) -- Remaining amount remainingAmount = MAX(targetAmount - currentAmount, 0) -- Current milestone level currentMilestoneLevel: if currentAmount >= 6 × monthlyExpenses → LEVEL_3 if currentAmount >= 3 × monthlyExpenses → LEVEL_2 if currentAmount >= 1 × monthlyExpenses → LEVEL_1 if currentAmount > 0 → LEVEL_0 else → null (not started) -- Estimated completion date averageMonthlyContribution = Σ(DEPOSIT + AUTO contributions in last 3 months) / 3 monthsToCompletion = CEIL(remainingAmount / averageMonthlyContribution) → Guard: if averageMonthlyContribution = 0 → "Set a monthly contribution to see estimate" estimatedCompletionDate = today + monthsToCompletion months -- Monthly growth rate (last 3 months average) monthlyGrowthRate = averageMonthlyContribution / MAX(currentAmount, 1) × 100 -- Consistency score monthsActive = months between createdAt and today (minimum 1) monthsWithContribution = COUNT(distinct months with ≥ 1 DEPOSIT or AUTO entry) consistencyScore = monthsWithContribution / monthsActive × 100 (0–100)

Protection Coverage Display

Beyond a raw percentage, the system displays the fund's protection in human terms:

-- "Days of coverage" display daysOfCoverage = FLOOR(currentAmount / (monthlyExpenses / 30)) -- Display logic if daysOfCoverage < 30: "X days of protection" if daysOfCoverage < 90: "X weeks of protection" if daysOfCoverage >= 90: "X months of protection" -- Example: currentAmount=15,000 MAD, monthlyExpenses=5,000 MAD -- daysOfCoverage = 15,000 / (5,000/30) = 90 days → "3 months of protection"

Live Update Guarantee

All computed values refresh within 100ms of any state change: new contribution, deleted contribution, changed monthlyExpenses, changed targetAmount. The UI never shows stale data.

10 Automation

Auto-Contribute

When isAutoContribute = true, the system creates an AUTO-type contribution on contributionDay each month for monthlyContribution MAD. The process:

  1. On the contribution day, the system checks: is the fund paused? Is the budget period open? Is the budget EMERGENCY_FUND category allocation sufficient?
  2. If all checks pass: creates an AUTO contribution, updates currentAmount, marks the budget category as spent.
  3. If the budget category has less than the scheduled contribution: contributes the available amount only; notifies the user of the shortfall.
  4. Sends a confirmation notification: "Monthly contribution of X MAD added automatically."

Salary-Based Contribution

When contributionSource = 'salary', the scheduled contribution fires on the salary day (from SPEC-SAL-001) rather than a fixed calendar day. This ensures the contribution happens when money is actually available.

Automatic Milestone Detection

Every time currentAmount is updated (by any means), the system evaluates currentMilestoneLevel and compares it to the level before the update. If a level has been crossed for the first time, the milestone celebration flow triggers automatically.

Future: Round-Up Savings (v2.0)

When bank synchronization is available, the app will offer to round up every transaction to the nearest 10 MAD and deposit the difference to the emergency fund. Example: a 73 MAD grocery purchase rounds up to 80 MAD, and 7 MAD flows to the fund. These appear as BONUS contributions.

15 Edge Cases

EC-01 Contribution Edited
User edits a recent contribution (within 30 days). The system recalculates all balanceAfter values for every contribution that follows the edited entry in chronological order, then updates currentAmount. This may trigger or un-trigger milestone events — milestone badges are not revoked, but the milestone-crossing notification does not re-fire.
EC-02 Contribution Deleted
Soft-deleted (deletedAt set). All subsequent balanceAfter values are recalculated. currentAmount is updated. If deletion causes the balance to drop below a milestone, a note is displayed: "Your balance is now below Level X. This milestone was earned and the badge is retained, but your fund needs rebuilding." No notification re-fires.
EC-03 Withdrawal Causes Negative Balance
System prevents currentAmount from going below 0. If withdrawal amount > currentAmount, an error is shown: "Withdrawal of X MAD exceeds your fund balance of Y MAD. Maximum withdrawal is Y MAD." The user may enter the exact balance to close the fund, which records a WITHDRAWAL equal to currentAmount and sets the balance to 0.
EC-04 Target Reduced Below Current Balance
User lowers the target to an amount below currentAmount. The system shows: "Your current balance (X MAD) already exceeds this target. Your fund is 100% complete." Completion percentage is capped at 100% in display. The system suggests archiving or setting a more ambitious target.
EC-05 Monthly Expenses Increased Significantly
User updates monthly expenses (e.g., moved to more expensive housing). Targets recalculate. If this causes completionPct to drop below a milestone threshold, no milestone badge is revoked. A note appears: "Your target has increased to X MAD due to updated expenses. You're now at Y% completion." A new recommended contribution is shown.
EC-06 Emergency Withdrawal (Actual Emergency)
User records a WITHDRAWAL for an actual emergency (job loss, medical). System responds empathetically: uses "withdrawal" not "debit." Post-withdrawal, shows a dedicated recovery card: "Emergency funds are meant for this. Here is your rebuild plan: contribute X MAD/month to restore Level Y in Z months." No negative framing or guilt-inducing language.
EC-07 Paused Contributions
When isPaused is true, auto-contribute is suspended. Budget category allocation for EMERGENCY_FUND is set to 0 for the next period. Health score Readiness component drops by 5 points. After 3 months of pause, a gentle re-engagement notification fires. The pause reason is stored and shown in the fund settings for context.
EC-08 Missed Contribution (Manual Mode)
No auto-contribution — user simply did not add a contribution this month. System records the month as "missed" in the consistency heatmap (grey cell). Consistency score drops proportionally. End-of-month notification fires (see §14). No punitive action — the fund simply doesn't grow that month.
EC-09 Duplicate Contribution
User accidentally adds the same amount on the same date twice. System detects potential duplicate: "A contribution of X MAD was already recorded today. Is this a separate contribution?" User confirms or cancels. No auto-deduplication — user intent is required. If confirmed, both entries are saved and both count toward the balance.
EC-10 Currency Changed
User changes their primary currency. New contributions are recorded in the new currency. Historical contributions retain their original currency notation and are displayed with a footnote: "Original: X MAD." All aggregate analytics normalize to the new currency using the stored exchange rate at the time of the change. The conversion event is recorded as an ADJUSTMENT entry for auditability.

Business Rules

Rule IDStatement
BR-EMF-01The Emergency Fund module is a singleton — one fund per user. Multiple funds are a v2.0 feature requiring a data model migration.
BR-EMF-02All monetary values are stored as integer centimes. Display conversion to MAD occurs only at the presentation layer.
BR-EMF-03currentAmount may never be negative. Any operation that would result in a negative balance is blocked with a clear error message.
BR-EMF-04All computed values (completionPct, remainingAmount, milestoneLevel, estimatedCompletionDate, consistencyScore) are derived at read time from stored data. They are never persisted.
BR-EMF-05Historical contribution records are never modified. Corrections are made via new ADJUSTMENT entries that reference the original. Deletions are soft-deletes only.
BR-EMF-06Milestone badges, once earned, are not revoked — even if the balance subsequently drops below the milestone threshold. Achievement records the event, not the current state.
BR-EMF-07The system uses a maximum of 3 months of contribution history to compute averageMonthlyContribution. Older data is used for trend analytics only, not for completion date projections.
BR-EMF-08When isAutoContribute is true, the AUTO contribution is treated as a budget expense in the EMERGENCY_FUND category. It cannot create a budget overdraft — if the budget category has insufficient allocation, only the available amount is contributed.
BR-EMF-09The contributionDay is capped at 28 to ensure validity in all months. If the user's preferred day is 29, 30, or 31, it is stored as 28 with a note.
BR-EMF-10Notification language for withdrawal events must never be punitive or judgmental. Emergency funds exist precisely to be used in emergencies. Post-withdrawal messaging focuses exclusively on recovery, not criticism.
